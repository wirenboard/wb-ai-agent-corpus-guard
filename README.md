# wb-ai-agent-corpus-guard

Плагин Discourse: не даёт случайно снять базу знаний с живого ИИ-агента.

## Зачем

**02.10.2026 живой бот поддержки пять часов отвечал без базы знаний.** Корпус пропал при обычной
правке агента в админке. Механизм — в двух местах Discourse AI.

**Первое.** Контроллер админки сохраняет файлы так:

```ruby
if @ai_agent.update(params.except(:rag_uploads))
  ...
  RagDocumentFragment.update_target_uploads(@ai_agent, attached_upload_ids(@ai_agent))
```

а список собирает из параметров запроса: `ai_agent_params[:rag_uploads].to_a`. Нет поля в запросе —
список пуст. А пустой список для `update_target_uploads` значит «снять всё»:

```ruby
if upload_ids.blank?
  RagDocumentFragment.where(target: target).destroy_all
  UploadReference.where(target: target).destroy_all
```

Фрагменты и привязки исчезают молча, инструмент `search_uploaded_documents` пропадает из запросов к
модели, бот продолжает отвечать — но уже без корпуса. В журнал действий это не попадает: поле файлов
штатный логгер не отслеживает, поэтому разбор по горячим следам ничего не показывает.

**Второе.** `AiAgent#regenerate_rag_fragments` при смене нарезки удаляет фрагменты и не пересобирает
их:

```ruby
if rag_chunk_tokens_changed? || rag_chunk_overlap_tokens_changed?
  RagDocumentFragment.where(target: self).delete_all
```

Для живого агента это тот же результат: корпус пуст, а пересчёт эмбеддингов — часы и деньги.

## Как работает

- Перехват `RagDocumentFragment.update_target_uploads` — через него идут все пути снятия файлов:
  админка, консоль, скрипты. Пустой список для **включённого** агента, у которого файлы **есть**,
  считается ошибкой, а не приказом: файлы остаются, правка самого агента применяется.
- Каждый такой случай пишется в `production.log` и в **журнал действий персонала**
  (`wb_corpus_guard_kept_uploads`), чтобы следующий разбор видел факт сразу.
- Смена нарезки (`rag_chunk_tokens`, `rag_chunk_overlap_tokens`) у включённого агента с файлами
  отклоняется с понятным сообщением. Нарезку меняют на отключённой копии и переключают корпус свапом.
- Выключённые агенты (staging-копии) под защиту не попадают: с ними работают как обычно.

## Настройки (Админка → Настройки → Плагины)

| настройка | по умолчанию | смысл |
|---|---|---|
| `wb_ai_agent_corpus_guard_enabled` | включено | выключать только когда файлы нужно снять осознанно |

## Проверка

`spec/` — 11 примеров на Discourse 2026.7.1 и 2026.8.0. Среди них запросный спек, воспроизводящий сам
случай: `PUT /admin/plugins/discourse-ai/ai-agents/:id.json` без поля `rag_uploads` — правка
применяется, корпус цел; с выключенным предохранителем тот же запрос корпус сносит. Остальное:
запись в журнал действий, непустой список проходит насквозь, выключенный агент не защищён, смена
нарезки отклоняется (в том числе когда агента выключают той же правкой) и разрешена на staging,
обычная правка промпта не задевает файлы. Мутации ловятся: без удержания пустого списка падают 2
примера, без проверки «агент включён» — 1, без запрета смены нарезки — 2.

Чего плагин не закрывает: прямое `delete_all` по таблицам из консоли и порчу корпуса «файлы есть, но
фрагменты негодные» — это работа ежедневного сторожа корпуса.

Установка на прод — строкой `git clone` в `app.yml` и перезапуском unicorn, как у других плагинов WB.
